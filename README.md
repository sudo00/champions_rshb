# Своё вино

Android-приложение и GPU-сервис для поиска вина по фотографии этикетки среди **2 103 проверенных карточек**. Сервер использует SAM 3, SigLIP2 и PaddleOCR; приложение показывает карточку, кандидатов поиска, рекомендации и историю сканирований.

- [Архитектура и ML-пайплайн](docs/ARCHITECTURE.md), [схема компонентов](docs/architecture.mmd).
- [Android: сборка и подключение](mobile_app/WineApp/README.md).
- [Разработка и проверки](docs/DEVELOPMENT.md), [служебные CLI](scripts/README.md).
- HTTP-контракт: [OpenAPI](docs/openapi.yaml), `/docs` и `/openapi.json` запущенного API.

## Установка и запуск

Нужны Linux x86_64, NVIDIA GPU с совместимым драйвером, Docker с Compose, NVIDIA Container Toolkit, Python 3.12+, `make` и `curl`. Проверенная конфигурация — RTX 3060 12 ГБ, драйвер NVIDIA 580.178.04. Docker должен иметь доступ к GPU и сети для загрузки образов и пакетов.

Из корня клонированного репозитория:

```bash
make setup
```

Команда создаёт env-файлы из шаблонов, скачивает три архива с Google Диска, проверяет SHA-256, распаковывает ресурсы, собирает образы и запускает FastAPI, GPU-worker, PostgreSQL, MinIO и RabbitMQ. Успех означает ответ 200 от `/ready`: ML-worker загружен, его версия каталога совпадает с API. `/health` отдельно проверяет только доступность API.

После старта контейнеров команда ждёт готовность до 300 секунд. При необходимости:

```bash
make setup READY_TIMEOUT_SECONDS=600
```

Адрес по умолчанию — `http://127.0.0.1:8000`; Swagger — `http://127.0.0.1:8000/docs`. DEV-профиль подключает исходники из рабочей копии. Для PROD без этих подключений:

```bash
make env
make prod
curl --fail http://127.0.0.1/ready
```

В шаблоне PROD внешний порт — 80. `make prod` запускает контейнеры, но готовность ML следует проверить отдельно.

### Ресурсы и зависимости

Архивы занимают суммарно около 8,24 ГБ. Распаковку выполняет скрипт на хосте; контейнеры подключают готовые папки только для чтения. Ручное копирование файлов внутрь контейнеров не требуется.

| Ресурс | Путь после распаковки |
|---|---|
| Модели SAM 3, SigLIP2, OCR, поисковый индекс и правила | `weights/wine-recognizer-v5-muscat-release/` |
| 2 103 изображения карточек | `data/deployment/catalog-images-v2/images/` |
| Текстовые векторы рекомендаций | `weights/recommendations-v2/` |

Размеры, SHA-256 и пути заданы в [build_env/artifacts.json](build_env/artifacts.json). Ссылки — в [build_env/gdrive.env.example](build_env/gdrive.env.example); локальные замены — в игнорируемом `build_env/gdrive.env`. Уже распакованные ресурсы повторно не скачиваются. Проверенные архивы в локальном кэше можно распаковать без повторной загрузки.

Каталог метаданных хранится в Git: [backend/catalog/catalog.jsonl](backend/catalog/catalog.jsonl). При первом запуске API создаёт таблицы PostgreSQL и загружает эти карточки. Состояния сканов и результаты сохраняются в Docker-томах. Включённый `IMPORT_CATALOG_ON_START=1` дополнительно запускает импорт с vino-svoe.ru; он может добавить карточки в БД, но не расширяет зафиксированный ML-индекс.

Python-пакеты скачиваются отдельно при сборке образов. Официальный сервер установочного пакета Paddle может работать медленно; первое развёртывание существенно дольше повторного запуска с Docker-кэшем. Сам wheel Paddle пока не входит в три архива ресурсов.

| Окружение в Docker | Зафиксированные зависимости |
|---|---|
| Vision и worker, `/opt/vision` | [requirements-vision.lock.txt](requirements-vision.lock.txt) |
| GPU OCR, `/opt/ocr` | [requirements-ocr-gpu.lock.txt](requirements-ocr-gpu.lock.txt) |
| FastAPI | [backend/api/requirements.lock.txt](backend/api/requirements.lock.txt) |

Образы используют Python 3.12.6. PyTorch и Paddle работают в отдельных окружениях и процессах; объединять их lock-файлы в одну среду не следует. Драйвер NVIDIA и Container Toolkit устанавливаются на хосте.

## Конфигурация

`make env` создаёт отсутствующие конфигурационные файлы и сохраняет уже существующие. После изменения ссылок в репозитории перенесите их и в свой `build_env/gdrive.env`.

| Где задаётся | Переменные | Назначение |
|---|---|---|
| `build_env/.env.dev`, `build_env/.env.prod` | `DOCKERFILE`, `API_PORTS`, `COMPOSE_PROJECT_NAME` | Dockerfile, внешний порт и имя Compose-проекта |
| `build_env/gdrive.env` или окружение команды загрузки | `GDRIVE_RECOGNIZER_URL`, `GDRIVE_CATALOG_IMAGES_URL`, `GDRIVE_RECOMMENDATIONS_URL` | Публичные ссылки на три архива; переменные процесса имеют приоритет |
| `environment` в `docker-compose.yml` | `DATABASE_URL`, `S3_ENDPOINT`, `S3_BUCKET_NAME`, `S3_PUBLIC_BASE_URL`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` | PostgreSQL и MinIO |
| Там же | `RABBITMQ_HOST`, `RABBITMQ_PORT`, `RABBITMQ_USER`, `RABBITMQ_PASS`, `RABBITMQ_VHOST`, `RABBITMQ_QUEUE_SCAN` | Подключение к очереди |
| Там же | `IMPORT_CATALOG_ON_START` | Дополнительный импорт каталога с сайта, по умолчанию `1` |
| `environment` API, через Compose override | `EVAL_WAIT_SECONDS` | Ожидание результата оценки; по умолчанию 9 секунд |
| `docker-compose.gpu.yml` | `WINE_BUNDLE_DIR`, `WINE_OCR_PYTHON`, `WINE_DEVICE`, `WINE_OCR_DEVICE` | Модели и устройства worker |
| Там же | `WINE_CATALOG_PATH`, `WINE_CATALOG_IMAGES`, `WINE_RECOMMENDATIONS_DIR` | Метаданные и ресурсы API |
| Аргументы `make` | `API_READY`, `READY_TIMEOUT_SECONDS` | Адрес проверки и срок ожидания готовности |

Корневой `.env` также создаётся из шаблона. В текущем Compose параметры контейнеров явно заданы в `environment`; изменение одноимённой строки только в `.env` их не переопределяет. Для своей инфраструктуры меняйте соответствующий Compose-профиль или подключайте override. Значения доступа в стандартном профиле предназначены для демонстрационного стенда.

После изменения `API_PORTS`, например на `8080:8000`, укажите адрес проверки:

```bash
make setup API_READY=http://127.0.0.1:8080/ready
```

Для Linux с неработающей bridge-сетью предусмотрен [docker-compose.host.yml](docker-compose.host.yml); нужен Compose с поддержкой `!reset`:

```bash
make setup COMPOSE_DEV='docker compose --env-file build_env/.env.dev -f docker-compose.yml -f docker-compose.gpu.yml -f docker-compose.dev.yml -f docker-compose.host.yml'
```

В host-профиле API слушает 8000, PostgreSQL — 5432, MinIO — 9000/9001, RabbitMQ — 5672/15672; порты должны быть свободны. По умолчанию имена контейнеров фиксированы, поэтому второй экземпляр требует отдельной конфигурации. Существующий стенд следует запускать с его прежним Compose-проектом и профилем.

## Оценка организаторами

Скрипт оценки предоставляет кейсодержатель. Он не входит в репозиторий команды. Наш сервис принимает его запросы через:

```text
POST /v1/eval/predict
Content-Type: multipart/form-data
Поле: image — исходная фотография
Ответ 200: {"slug":"идентификатор-карточки"}
```

Маршрут проходит через настоящие MinIO, RabbitMQ и GPU-worker. Он возвращает поисковый Top-1 с уточнением по проверенной сладости, без рекомендаций и без применения отказа по отсутствию в каталоге. Если кандидатов нет, возвращается `{"slug":"unknown"}`. Время каждого HTTP-запроса измеряет оценочный скрипт; отдельного поля времени в этом JSON нет.

Перед прогоном дождитесь `/ready`, отправляйте оригинальные фото последовательно. Проверка одного изображения с сохранением результата и выводом времени в секундах:

```bash
curl --fail http://127.0.0.1:8000/ready
curl --fail --silent --show-error --max-time 10 \
  --form 'image=@photo.jpg' \
  --output result.json \
  --write-out 'http=%{http_code} time_total=%{time_total}s\n' \
  http://127.0.0.1:8000/v1/eval/predict
```

API ограничивает ожидание девятью секундами. Ошибки: 422 — некорректное фото; 503 — ML или инфраструктура недоступны; 504 — результат не получен за отведённое время; 500 — ошибка распознавания. Задание может завершиться в очереди после HTTP-тайм-аута. Контракт и срок ожидания согласуются со скриптом кейсодержателя.

## Мобильное приложение и пользовательский API

Android собирается отдельно: JDK 17+, Android SDK 35, `./gradlew :app:assembleDebug` из `mobile_app/WineApp`. Адрес API задаётся через `WINE_API_BASE_URL` в локальной конфигурации; подробности — в [Android README](mobile_app/WineApp/README.md). Модель камеры 9,3 МиБ и её JSON-контракт включены в Git; серверные веса для сборки APK не нужны.

```text
POST /v1/wines/scan                       → scanId
GET  /v1/wines/scan/{scanId}               → pending / processing / done / failed
POST /v1/wines/scan/{scanId}/confirmation  → подтверждение выбранной карточки
```

Первый запрос: JSON `{"imageBase64":"...","includeAlternatives":true}`. Подтверждение: `{"slug":"..."}`. `includeAlternatives` ограничивает выдачу пятью или одним кандидатом, не меняя ранжирование. Полный ответ содержит карточки, OCR, области на фото, рекомендации и `timingsSeconds` отдельных стадий worker; эти времена не включают весь HTTP-путь и ожидание в очереди.

Для ручной проверки полного пользовательского ответа:

```bash
python3 scripts/scan_api.py photo.jpg --base http://127.0.0.1:8000 --output result.json
```

История, цифровой сомелье, рулетка и винный путь описаны в [архитектуре](docs/ARCHITECTURE.md#дополнительные-функции).

## Ограничения

- Принимается одна фотография до 30 МиБ и 25 мегапикселей; многокадровые изображения отклоняются.
- Один worker обрабатывает одну задачу за раз. Параллельные запросы ожидают очередь и могут превысить срок оценки.
- Поиск ограничен согласованным каталогом из bundle. Обновление карточек в БД само по себе не пересчитывает эмбеддинги.
- Похожие этикетки, блики, размытие, перекрытия и несколько бутылок в кадре могут приводить к ошибкам. Отказ по отсутствию вина остаётся эвристикой.
- `score` и `matchScore` — оценки сходства, не вероятности. Год сам по себе не является основанием считать вино отсутствующим.
- Локальный детектор камеры экспериментальный и может срабатывать на другие товары. Скорость зависит от телефона, GPU сервера, разрешения и очереди.
- Подключения внешнего сомелье и других мобильных сервисов настраиваются отдельно; они не участвуют в оценочном ML-маршруте.

## Проверки и состав репозитория

```bash
make test-api
python3 scripts/test_download_gdrive_weights.py
```

Первое — API-тесты в Docker без GPU и работающего стека; второе — проверки загрузчика без сети и весов. Для локальных Python-окружений и Android см. [DEVELOPMENT.md](docs/DEVELOPMENT.md).

В Git находятся код, тесты компонентов, метаданные каталога, lock-файлы, документация и одна мобильная модель. Веса сервера, фото, секреты, локальные отчёты, исследовательские скрипты и архив внутренних документов (`local_docs/`) исключены из Git. Четыре общих документа в `docs` сохранены; внутренние handoff-инструкции и примеры не нужны для развёртывания.

`make logs` показывает логи, `make down` останавливает стек с сохранением томов, **`make ddown` удаляет тома PostgreSQL, MinIO и RabbitMQ**.
