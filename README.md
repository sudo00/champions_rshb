# Своё вино

Android-приложение и GPU-сервис для поиска вина по фотографии среди **2 103 проверенных карточек**.

Телефон готовит фото до 2560 px / JPEG 90; сервер выделяет бутылку и этикетку через SAM 3, строит виды, выполняет OCR и визуальный поиск SigLIP2. Ответ содержит кандидатов, `matchScore`, прочитанные надписи и рекомендации.

## Что показывает приложение

- **Top-1 выше 70/100:** автоматическое «Ваше вино» и рекомендации; ручной выбор позволяет исправить результат. Отказ сервера имеет приоритет.
- **Пользователь подтвердил «Это моё вино»:** выбранная карточка и «Рекомендуем также» по её свойствам и текстовому описанию.
- **Совпадение не подтверждено:** Top-5 поиска с оценкой совпадения, затем рекомендации по первому кандидату с соответствующей пометкой.
- **Вино не найдено в каталоге:** сообщение и отдельные рекомендации только по характеристикам, прочитанным на этикетке. Если данных недостаточно, подбор остаётся пустым.

Подтверждение пользователя сохраняется отдельно от ML-статуса. `matchScore` — оценка сходства 0–1, не вероятность; клиент показывает её как баллы из 100. Порядок поиска не меняется, оценки пятёрки не нормируются на сумму.

Сканы камеры и галереи автоматически сохраняются с фото и статусом. Подтверждение обновляет ту же запись без дубля.

В камере локальный YOLO26n автоматически запускает съёмку устойчивой центральной этикетки. Рамки детектора и переключатель не показываются. При старте распознавания вибрация плавно нарастает; при получении результата — короткий акцент с быстрым спадом. Детектор может путать вино с другими товарами; ручная кнопка доступна. Серверное распознавание по-прежнему выполняется по отдельному качественному фото.

## Android без локальной видеокарты

1. Открыть `mobile_app/WineApp` в Android Studio, установить JDK 17+ и Android SDK 35.
2. Указать `WINE_API_BASE_URL` в игнорируемом `local.properties`; образец — `local.properties.example`. Адрес общего сервера передаётся отдельно.
3. Собрать `./gradlew :app:assembleDebug`. Debug-версия устанавливается как `com.wineapp.dev`.

Каталог, изображения, OCR и поиск клиент получает через API. Серверные веса и папка `data` мобильному разработчику не нужны. **Единственная мобильная модель, 9,3 МиБ, включена в Git** в `app/src/main/assets/models/` вместе с JSON-контрактом и SHA256.

## Запуск собственного сервера

Нужны Linux, NVIDIA GPU, Docker Compose и NVIDIA Container Toolkit. Сначала получить и распаковать ресурсы из [build_env/artifacts.json](build_env/artifacts.json):

| Ресурс | Локальный путь |
|---|---|
| Модели, индекс и правила ML | `weights/wine-recognizer-v5-sugar-release/` |
| Изображения каталога | `data/deployment/catalog-images/` |
| Текстовый индекс рекомендаций | `weights/recommendations-v1/` |

```bash
make env
make dev
curl --fail http://localhost:8000/ready
```

Docker устанавливает закреплённые зависимости, но **не скачивает автоматически серверные веса и картинки**. Ссылки на архивы нужно получить у владельца развёртывания; SHA256 указаны в манифесте. Без текстового индекса подбор работает только по атрибутам. `/health` проверяет API, `/ready` — готовность распознавания; Swagger: `http://localhost:8000/docs`.

## API сканирования

```text
POST /v1/wines/scan                           → scanId
GET  /v1/wines/scan/{scanId}                   → pending / processing / done / failed
POST /v1/wines/scan/{scanId}/confirmation      → сохранить выбранный slug, обновить рекомендации
```

В первом запросе JSON `{ "imageBase64": "...", "includeAlternatives": true }`; в подтверждении — `{ "slug": "выбранный-кандидат" }`. `includeAlternatives` ограничивает выдачу пятью или одной карточкой.

```bash
python3 scripts/scan_api.py photo.jpg --base http://localhost:8000 --output result.json
```

Для оценки организаторов: `POST /v1/eval/predict`, multipart `image`, ответ `{ "slug": "..." }`. Он сохраняет поисковый Top-1 и обходит отказ; пользовательское подтверждение и рекомендации не меняют этот маршрут. В оценку передавать оригинальные фотографии без телефонного сжатия.

## Структура и точки входа

```text
mobile_app/WineApp/       Android, локальный детектор камеры
backend/api/             FastAPI, карточки, рекомендации, подтверждение пользователя
backend/worker/          очередь и recognition.run(image, includeAlternatives)
worker/pipeline/         численное ядро: WineRecognizer.predict
worker/image_preprocessing.py  общая подготовка фото для явного вызова из CLI
backend/catalog/         проверенный каталог и контрольные суммы
build_env/               Dockerfiles, шаблоны конфигурации, манифест ресурсов
scripts/                 CLI запуска, проверки, подготовки фото, упаковки и настройки сети
```

Фото → API → MinIO / RabbitMQ → worker → PostgreSQL → polling результата. API не загружает GPU-модели. `worker/pipeline/` входит в проверяемый bundle: изменение численного кода требует согласованной пересборки ресурсов.

`scripts/` содержит только отдельно запускаемые команды и не является зависимостью приложения. Повторно используемые функции находятся в модулях соответствующих компонентов; CLI импортируют их, а не наоборот.

## Что хранится в Git

Рабочий код, backend/Android-тесты, каталог, lock-файлы, общая документация, Gradle Wrapper и **одна выбранная мобильная модель**. Серверные веса, фотографии, отчёты, исследовательские скрипты и окружения остаются локально. Для `docs/` и `scripts/` действует явный разрешённый список в `.gitignore`; локальных файлов на ML-машине больше, чем попадает в репозиторий.

Не добавлять адрес развёртывания, `local.properties`, `.env`, ключи и локальные пути. `make down` останавливает стек; `make ddown` также удаляет тома базы и хранилища.
