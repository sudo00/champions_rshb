# Служебные команды

Здесь находятся только самостоятельно запускаемые команды. Рабочий ML-код
находится в `worker/pipeline/`, backend вызывает его через
`backend/worker/recognition.py`. Общая подготовка изображений —
`worker/image_preprocessing.py`; CLI `prepare_scan_image.py` вызывает этот модуль.
API, worker и мобильное приложение не импортируют `scripts/`; Docker исключает
эту папку. Зависимость направлена от CLI к библиотекам приложения.

| Файл | Назначение |
|---|---|
| `scan_api.py` | Отправить фото в запущенный API и сохранить результат; без GPU на клиенте |
| `check_recognition_api.py` | Проверить API по локальным сохранённым результатам; нужны отдельные тестовые данные |
| `recognize_photo.py` | Прямой вызов ML-класса; нужен GPU и проверенный bundle |
| `prepare_scan_image.py` | Подготовить телефонное фото: EXIF, до 2560 px, JPEG 90 |
| `package_recognizer.py` | Упаковать и проверить готовый bundle |
| `export_recognizer_bundle.py` | Экспортировать bundle из локальных ML-артефактов или перепаковать существующий |
| `package_catalog_images.py` | Упаковать изображения проверенного каталога |
| `install_api_network.sh` | Установить локальное правило маршрутизации ответов API через провайдера |
| `download_gdrive_weights.py` | Скачать архивы весов с публичных ссылок Google Диска и распаковать их; вызывается из `make install` и `make setup` |

Пример: `python3 scripts/scan_api.py photo.jpg --base http://localhost:8000 --output result.json`.
Для оценки отправляйте оригинал; подготовка до 2560 предназначена для телефонного сценария.
Веса и изображения передаются отдельными архивами, а не через Git.

Исследовательские скрипты исключены из Git. На ML-машине они могут оставаться
в этой папке; Docker-контекст их не включает. Новые общие утилиты нужно явно
добавлять в разрешённый список `.gitignore`.

## API при включённом VPN

Указать LAN IPv4 в игнорируемом `.env.network` по образцу `build_env/network.env.example`, включить VPN и выполнить `bash scripts/install_api_network.sh`. Скрипт определяет метку обхода VPN для инвертированного правила с приоритетом 0/1 и устанавливает отдельную nftables-таблицу `wine_api_routing`: маркируются только исходящие TCP-пакеты с локального IP и порта 8000. Остальной трафик не меняется. Служба `wine-api-routing.service` восстанавливает исключение после перезагрузки.

Если VPN изменил метку или LAN-адрес, повторить установку. При нескольких метках можно явно задать `WINE_API_VPN_BYPASS_MARK` в локальном файле. Не менять приоритет стандартной таблицы `local` и не отключать firewall. Для удаления исключения: `sudo systemctl disable --now wine-api-routing.service`.
