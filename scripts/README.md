# Служебные команды

Рабочий ML-код находится в `worker/pipeline/`, backend вызывает его через
`backend/worker/recognition.py`. Эти утилиты не нужны worker во время инференса.

| Файл | Назначение |
|---|---|
| `scan_api.py` | Отправить фото в запущенный API и сохранить результат; без GPU на клиенте |
| `check_recognition_api.py` | Проверить API по локальным сохранённым результатам; нужны отдельные тестовые данные |
| `recognize_photo.py` | Прямой вызов ML-класса; нужен GPU и проверенный bundle |
| `prepare_scan_image.py` | Подготовить телефонное фото: EXIF, до 2560 px, JPEG 90 |
| `image_preprocessing.py` | Общая реализация подготовки фото для CLI |
| `package_recognizer.py` | Упаковать и проверить готовый bundle |
| `export_recognizer_bundle.py` | Экспортировать bundle из локальных ML-артефактов или перепаковать существующий |
| `package_catalog_images.py` | Упаковать изображения проверенного каталога |
| `install_api_network.sh` | Установить локальное правило маршрутизации ответов API через провайдера |

Пример: `python3 scripts/scan_api.py photo.jpg --base http://localhost:8000 --output result.json`.
Для оценки отправляйте оригинал; подготовка до 2560 предназначена для телефонного сценария.
Веса и изображения передаются отдельными архивами, а не через Git.

Исследовательские скрипты исключены из Git. На ML-машине они могут оставаться
в этой папке; Docker-контекст их не включает. Новые общие утилиты нужно явно
добавлять в разрешённый список `.gitignore`.
